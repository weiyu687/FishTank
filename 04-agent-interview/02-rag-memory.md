# Agent 应用开发面试 02：RAG、上下文与记忆

[TOC]

## 1. RAG 的基本链路是什么？

离线：采集、解析、清洗、切分、添加元数据、索引。在线：理解查询、召回、过滤、重排、组织证据、生成与引用校验。任何环节都可能丢失答案，不能把问题统一归咎于模型。

追问“如何定位答错”：先检查原始资料是否包含答案，再看候选是否召回、重排后是否保留、提示词是否含证据、最后检查生成是否忠实。

## 2. Chunk 大小怎么选？

按文档结构与任务粒度选择。过小会切断定义、条件和表格；过大会稀释向量语义、挤占上下文。优先保留标题路径、段落和表格结构，必要时小块召回后扩展父块。

用固定问题集比较召回率、引用精度和 token 成本，不报一个对所有场景通用的数字。overlap 会增加冗余，需要去重与预算控制。

## 3. 向量检索、BM25、混合检索怎么比较？

向量适合语义近似，关键词适合精确术语、编号和罕见词。混合检索结合二者，随后融合或重排。不同检索分数通常不在同一尺度，不能不加校准直接相加。

例如错误代码 E104 的查询需要保留精确匹配；“账户被锁定怎么办”可能依赖语义召回。对具体业务分布做分类评估。

## 4. Reranker 的价值与代价？

在初步候选上进一步判断查询与段落相关性，提高前列证据质量。代价是时延、计算成本和额外故障点。它无法找回初次召回完全遗漏的文档，所以先保证候选覆盖，再优化排序。

## 5. Query rewrite 什么时候有用？

对省略、指代和领域同义词有帮助，例如把“那它怎么退款”结合历史改写成明确商品问题。风险是误解用户意图或注入未经确认的条件。保留原查询，必要时并行检索原文与改写版，并记录改写结果。

## 6. 怎样降低 RAG 幻觉？

提高资料覆盖与召回质量、明确答案依据、要求可定位引用、对关键字段做后验检查，并支持缺证拒答。引用 URL 存在不代表它支持该结论，需核对引用段落与主张的对应关系。

追问“如何量化”：答案正确率、证据支持率、引用准确率、无答案任务拒答率。拒答过多也会损害有效回答覆盖率。

## 7. Agentic RAG 与固定 RAG 的区别？

固定 RAG 通常按预设检索生成链路执行；Agentic RAG 允许模型决定何时检索、改写、访问哪个源以及是否继续搜索。适合需要多次探索的问题，但更难控制成本与延迟。[检索指南](https://docs.langchain.com/oss/python/deepagents/retrieval)

对简单问题优先固定链路，对复杂问题升级到动态搜索，是可测试的混合方案。必须限制循环次数并验证新增检索是否真正带来信息增益。

## 8. RAG、微调和记忆如何选择？

RAG 提供可更新、可引用的外部知识；微调通常用于行为模式、格式和任务适配；记忆保存用户或任务历史中持续有用的信息。三者可组合。需要频繁更新的政策不宜只写进模型参数；个人偏好不应该混入所有用户共享的知识库。

## 9. 上下文窗口更大为什么仍需管理？

窗口容量不等于有效利用率。冗余、矛盾证据和大量工具描述会增加成本、延迟和注意力干扰。给任务目标、近期交互、证据、规则和输出留预算，淘汰低价值重复内容。

摘要需要保留约束、关键事实、证据路径和未完成项。对于法律条款、数字和业务状态应保留可回查原文，不能仅依赖自然语言摘要。

## 10. 短期和长期记忆的实现差异？

短期主要是线程状态恢复；长期是跨线程信息的读取和更新。持久化只是基础，还要设计何时写、写什么、何时读、冲突如何解决、何时失效。不能把全部历史无限追加后称为记忆系统。

具体实验见 [Deep Agents 记忆实验](../02-langchain/deepagents/02-memory-lab.md)。用随机标记、新线程和独立进程排除上下文泄漏。

## 11. 记忆提取怎样避免污染？

先判断信息的来源、稳定性和适用范围；区分用户明确偏好、模型推断和外部资料。低置信度推断不能提升成确定事实。对规则类记忆使用只读来源，对个人偏好保留更新和删除入口。

写入流程可以是候选提取器输出结构化记录，再由代码校验 scope、证据和有效期。高风险信息需要人工确认或禁止记忆。

## 12. 多租户检索怎么防止串数据？

在服务端根据已验证身份限定检索范围。过滤条件应作用于实际查询和读取环节，不能只在 prompt 中告诉模型不要看别人的资料。缓存键、向量库过滤、文件根目录和 trace 权限也必须包含相同身份边界。

测试不仅问“你知道 Alice 的秘密吗”，还要尝试伪造 user_id、构造路径、猜测文档 ID、利用共享缓存和重排接口绕过过滤。

## 13. 记忆如何评估？

分别测写入准确率、有效信息召回、错误记忆采用率、冲突解决、跨用户隔离、删除后遗忘和成本。把读取失败分成存储缺失、检索未命中、上下文未注入、模型未采用四类。

测试集包含新增、更新、重复、过期、删除、并发及攻击样例。一次聊天中的正确复述不是长期记忆评估。

## 14. 文档更新后如何保持索引一致？

维护文档 ID、内容版本、更新时间和权限版本。增量更新时撤销旧块，再写入新块，或用索引版本切换避免混合状态。删除源文件应触发索引和缓存清理。回答中记录所用版本，便于追溯。

## 面试练习
